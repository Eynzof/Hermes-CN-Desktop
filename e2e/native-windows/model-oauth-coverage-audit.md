# 模型 OAuth 取消流程验收

OAuth 完成登录、持久凭据和登出需要实际账号，仍保留为 MODEL-006。无需账号的设备码发起与取消从原清单拆出为 MODEL-010，避免把可测试步骤一并归为账号阻塞；两者合计仍覆盖原需求。

## Windows 实际执行

`runs/20260907T105653Z`，`61-model-oauth-cancel.spec.ts`，官方 Nous Portal，独立且未登录的默认测试档案。

- Desktop 发起真实设备码请求，收到设备码，界面展示与剪贴板内容一致；原生 Chrome 实际打开官方返回的验证地址。没有替换 OAuth 服务或模型接口。
- 正常关闭弹窗后，UI 发出取消请求；随后只读轮询返回 404。点击刷新后仍未连接，`auth.json` 摘要未变化。这些步骤通过并保存了独立检查点附件。
- 再次点击登录，在请求发出 34 ms 后关闭仍显示“正在启动授权流程”的弹窗。官方响应在关闭 1056 ms 后返回；对应 Core 会话仍为 pending，且又打开了官方验证页面。会话取消断言实际收到 HTTP 200，整项失败（WIN-024）。
- 测试结束仅清理本次创建的两个会话，并关闭已核对官方域名的两个标签页。迟到会话的直接 API 清理不计为 UI 取消成功；凭据摘要与模型配置没有变化。

脚本只观察并原样转发原生 IPC 请求和响应，没有注入延迟、替换响应、改动计时器或直接设置 UI 状态。事件附件区分请求发起、响应完成、弹窗关闭和清理时间。第一阶段已视觉检查实际 Windows 浏览器截图；第二阶段的操作和断言均在脚本中。

## 实现依据与未测范围

Desktop `web/src/routes/settings-oauth-section.tsx` 的 `handleClose` 仅在 `sessionIdRef.current` 已有值时取消。启动请求的 Promise 在组件卸载后仍执行，写入迟到 session ID 并调用 `openExternalUrl`；当前没有卸载后的会话取消路径。这与上述实际时序一致。

没有登录 Nous 账号、购买订阅、调用 Nous 模型或验证已登录后的登出。主模型仍为官方 `deepseek-v4-flash`。MODEL-006 保持未运行，MODEL-010 不替代它。
