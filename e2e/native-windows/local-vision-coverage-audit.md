图片为 320×320 的四色色块和白色间隙，色块位置随机，文件名为 UUID，不带颜色答案。后续两个阶段避免相同排列。脚本通过 Windows 文件选择器添加附件，并逐个比较模型输出中的实际颜色顺序；不会让模型运行代码取像素来冒充视觉能力。辅助流程要求唯一工具为 vision_analyze。

当前脚本在配置保存后重新加载页面，核对模型和图片模式仍然保存，再执行独立识图。这是为了把持久配置后的图片路径与“不重载时配置同步”问题分开；前面的失败不会因重载而撤销。原生阶段发现工具调用会自动保存会话、点击真实停止按钮并等待回合结束；原生失败后仍继续辅助阶段及配置恢复。

Core 的 run_agent.py::_prepare_messages_for_non_vision_model 会在能力判断为否时把图片替换为辅助视觉说明，且该判断不同于强制 native 的界面选择。现有日志与这条路径一致，但尚未把能力判断失败的全部触发条件定位完毕；不把推测当作已证明根因，也不修改产品代码。

工具可用性还有两层缓存：tools/registry.py 的 check_fn 结果有效 30 秒；model_tools.py 的工具定义按配置文件 mtime/size 等字段缓存，本身没有时间过期项。123616Z 在 20:37:03 记录视觉检查不可用，20:37:11 的辅助回合没有视觉工具。脚本现保留即时失败，再分别测试真实等待 35 秒后的新会话，以及从 UI 将辅助超时 300 改为 301、重新保存后的新会话。两者是独立恢复场景，不能把后续成功改记成即时配置生效通过；具体执行与否以附件为准。
