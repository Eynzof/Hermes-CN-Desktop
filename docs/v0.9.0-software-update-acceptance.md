# v0.9.0 软件更新实现与验收

2026-09-09。本轮代码已实现用户更新流程与高级能力分层，Windows 原生更新专项通过。正式发布仍受更新服务、正式签名产物及 macOS 尚未完成的验收阻塞。全部工作留在本地及授权 Windows 测试机，未 push、触发 CI/CD 或公开发布。

## 产品行为

统一入口为 `/updates`：底部右侧、关于和内核页进入同一页面，内核离线仍可访问。默认展示软件版本、更新状态、说明、大小、生效影响及主要操作。组件更新只改变对应组件版本，不将 Desktop 版本标为升级。

启动 60 秒后检查，此后约 12 小时检查；有可用更新且应用在前台、没有任务、编辑或其他 Modal 时提醒。同一渠道、目标及提醒阶段关闭后 24 小时内不重复弹出，底部入口保留。下载和应用分别由用户触发，任务结束只提醒、不自动重启。

“高级更新选项”默认收起，保留渠道及 nightly 原映射、更新源与校验、邀请导入与系统凭据、组件检查/更新/回退、诊断和受开发环境限制的后端热更新。测试渠道和自定义更新源在默认区域显示提示。切换设置清除旧计划并重新检查，切回正式渠道不自动降级。

桌面 Rust 端持久化更新计划并广播状态，所有普通和高级操作共享执行锁。下载目标固定，应用前复核授权、摘要、签名及兼容性。优先整包；组件按 Core、UI 顺序生效，失败停止。Core 活动登记涵盖对话、子任务和 cron 的已领取任务，生效前与新任务领取共用跨进程维护锁。外部 Core 不由本机停止或升级。

Core 生效核对实际 `/api/version`，失败恢复上一版本；UI 严格比较版本，避免旧热更新缓存覆盖新安装包，挂载回执验证构建标识，未确认或超时恢复旧界面。macOS 整包安装成功后显式重启。应用前保存草稿和页面位置；原始技术错误仅在高级详情展示。

失败安装测试在测试 NSIS 的退出码 77 注入点发生，核实原应用重新打开、旧版本和摘要未变；它不能证明任意中途系统故障都可完整回滚安装目录。12 小时检查和 24 小时同版抑制的完整时间边界由针对性测试覆盖，本轮没有实等 24 小时。

## 发布前仍需完成

1. **正式默认服务可用**：本机检查正式 shell 端点发生 TLS EOF；默认 Runtime 地址返回 HTML 而非清单；旧 `latest.json` 仍为 v0.7.0。代码内置地址和空配置迁移已经实现，服务可用性尚未达标。不可把本机夹具通过当成公网正式更新通过。
2. **最终分发签名**：当前 Windows 为 Acceptance 包，使用测试更新签名、测试 CA 信任和 zlib 安装压缩，未完成正式 Authenticode 验收。macOS 使用 Developer ID 签名，但尚未公证；需要可用的 notarytool 配置或 App Store Connect Issuer ID。
3. **macOS 原生整包链路**：本机夹具证书信任需要系统认证，完成后继续下载、应用、自动重启、实际版本和数据保留验收。不能以构建成功或签名验证代替此项。
4. **正式升级矩阵**：最终字节下补验已有正式版/内部版本→0.9.0，以及 0.9.0→后续正式候选；公开 nightly 分发服务和权限亦需使用对应实际账号/端点验收。本轮保留其原逻辑并回归渠道设置，未发布 nightly。

macOS 验收脚本入口见 `e2e/native-macos/README.md`；Windows 既有脚本已固化本轮流程。服务部署和公开发布不属于本轮执行范围。
