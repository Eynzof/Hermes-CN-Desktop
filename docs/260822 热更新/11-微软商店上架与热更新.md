# 11. 微软商店边界

## 1. 本期范围

本期自动更新面向 GitHub Release 直发的 Tauri/NSIS 与 Linux AppImage。Microsoft Store 是独立分发渠道，不作为本期热更新上线前置条件，也不能让 Store 包绕过 Partner Center 政策。

## 2. Direct 与 Store 分开

| 维度 | Direct（本方案） | Microsoft Store |
|---|---|---|
| 安装入口 | 官网/GitHub | Microsoft Store |
| 持久制品/CDN | GitHub Release + Cloudflare 缓存 | Microsoft/Partner Center |
| OS 更新策略 | Tauri updater + D1 灰度 | Store 更新机制/Partner Center |
| 签名 | Authenticode + Tauri signature | Store 要求的签名/认证 |
| 版本发现 | Cloudflare control | Store 服务 |

未来若保留同一应用的 Store 构建，必须在构建期写明 distribution，并在诊断页显示；Store build 默认禁用本方案的 Tauri shell updater，避免 Store 与应用内部安装器争夺同一个版本。

## 3. 不可复用的发布动作

- Direct stable 的 promotion 不能代表 Store submission 已获批。
- Store candidate 不能因为 D1 已 100% 就跳过 Partner Center。
- 预发布/内测不能改官网 `latest.json` 或伪装成 Store stable。
- Store 资产不上传 R2、CNB 或 Gitea；其长期源由 Microsoft 管理。

## 4. 若未来启用 Store

另开 RFC，至少确认：包格式（MSIX/EXE/MSI）、WebView2 离线依赖、应用身份、Partner Center 产品、分发区域、签名、自动更新冲突、逐步推出和 halt 行为。Microsoft 的 [Store submission API](https://learn.microsoft.com/windows/apps/publish/store-submission-api) 可在首次人工建产品后自动化 submission，但其 service principal 不能同时拥有 Cloudflare production promotion 权限。

已升级用户同样不能依靠 Store 自动降级；出现问题应 halt/暂停并发布更高版本修复。
