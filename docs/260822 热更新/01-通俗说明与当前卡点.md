# 01. 通俗说明与当前卡点

## 1. 这套系统要做什么

可以把它理解为“门卫 + 快递中转站”：

1. GitHub Release 是仓库，只保存签名后的正式字节。
2. Cloudflare 控制 Worker 是门卫，判断这台机器、这个 ring、这个版本今天能不能更新。
3. D1 是门卫的名单和开关，保存设备、灰度比例、暂停/撤销状态和审计。
4. Cloudflare 下载 Worker 是快递中转站，缓存 GitHub 的版本化安装包，不长期另存一份。
5. 若中转站下载发生超时、429 或 5xx，客户端改取门卫已经批准的同一 GitHub 包。
6. Tauri 签名和 SHA-256 是封条；来源变了，封条规则不变。

因此不需要一台长期运行的“热更新服务器”，也不需要对象存储。需要的是两个很小的 Worker、一个 D1 和 GitHub Release。

## 3. 当前卡点

| 卡点 | 为什么是卡点 | 处理方式 |
|---|---|---|
| Cloudflare 管理 token 尚未通过 Actions 管理工作流验证 | 三包构建与 Environment 审批已跑通，但 `workflow_dispatch` 管理工作流在进入默认分支前不能作为正式入口 | 合并前保持本地 staging CLI；合并后先跑只读 `release status`，再允许 production 之外的写操作 |
| Windows 正式 Authenticode 尚未采购 | staging 自签名身份只对专机显式信任；Tauri 签名也不能替代 Windows 对 EXE 发布者的信任 | 采购/配置证书和 RFC 3161 时间戳，canary/beta/stable 强制验证 |
| Cloudflare 免费网络无大陆 SLA | 自定义域名在一台机器可达不代表全国可达；真机直连 GitHub 约 60 KB/s，约 40 分钟后响应体中断 | 多运营商采样；控制面失败保持当前版；GitHub 只做 best-effort 回退，不宣传为大陆加速 |
| macOS/Linux 尚未真机验收 | Windows 通过不能替代 notarization、双架构重启或 AppImage 行为 | 在扩大到 canary 前完成 macOS arm64/x64 和 Linux AppImage 独立验收 |
| 只有一次独立候选通过 | 缓存命中、GitHub 回源和 CI 状态可能偶然 | 用新的 tag/SHA 再跑一次完整候选，并观察 14 天后再决定旧 R2 清理 |

## 4. 什么已经解决

- Desktop `0.8.x ↔ Core 0.20.x` 已进入机器可读兼容矩阵。
- 客户端不会把 Bearer token 发送给下载 Worker 或 GitHub。
- Cloudflare 失败只对可恢复的网络/429/5xx做一次完整包重下；签名、格式、401/403、404不回退。
- 控制面不可达不会去 GitHub发现新版本。
- token 可从一次性邀请导入系统凭据库，配置文件只保存 endpoint/channel/device ID。
- 下载完成可“立即重启/稍后”，Windows pending 包可在下次启动恢复。
- 发布注册只能从真实 GitHub资产和 `release-record.json` 反推 SHA、大小、签名和 Core 元数据。
- promotion、调比例、暂停、撤销都有 D1 审计事件。
- 两个 staging Worker 和 D1 追加迁移已经部署；production 未部署。
- PR #592 的 Windows 三包工作流已用 required reviewer 正常批准并全绿；公开 prerelease 始终不是 latest，Landing 保持 `v0.7.0`。
- `primelab-win` 已完成 Cloudflare 主源安装、GitHub fallback 功能验证、401、404、坏签名和 pause 后安装阻止；candidate 最终为 paused/0%，badsig 为 revoked/0%。
- `primelab-win` runner 已使用专用标签在线，运行于 Session 1 且非提升权限；Session 0 无法可靠创建 WebView2，提升权限又会让 WebView2 忽略 CDP flags。
- staging Cloudflare token、Tauri 私钥、专机 token、Runtime tag、baseline 路径和 staging Authenticode 身份已进入受保护 Environment；production 身份仍未创建。

## 5. 不应误解的边界

- “指定用户可更新”不等于“安装包保密”。公开 prerelease 的 URL 可能被任何人获得，但应用只向被授权设备自动下发。
- GitHub 是下载备用源，不是发现备用源。
- 暂停只能阻止新安装；已经升级的机器不会自动降级。
- `stable` 不由 beta 记录改名，而是重新用正式版本号和 production 身份构建。
- 第一版不做差分或真正断点续传；回退会重新下载约 185 MB 的完整包。
