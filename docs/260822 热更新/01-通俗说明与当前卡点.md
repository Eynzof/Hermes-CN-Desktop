# 01. 通俗说明与当前卡点

## 1. 这套系统要做什么

可以把它理解为“门卫 + 快递中转站”：

1. GitHub Release 是仓库，只保存签名后的正式字节。
2. Cloudflare 控制 Worker 是门卫，判断这台机器、这个 ring、这个版本今天能不能更新。
3. D1 是门卫的名单和开关，保存设备、灰度比例、暂停/撤销状态和审计。
4. Cloudflare 下载 Worker 是快递中转站，缓存 GitHub 的版本化安装包，不长期另存一份。
5. 若中转站下载发生超时、429 或 5xx，客户端改取门卫已经批准的同一 GitHub 包。
6. Tauri 签名和 SHA-256 是封条；来源变了，封条规则不变。

因此不需要一台长期运行的“热更新服务器”，也不需要对象存储。需要的是两个很小的 Worker、一个 D1 和 GitHub Release。

## 2. 我们还需要什么

### 开始真实 prototype 验收前

- 一个新的、公开但标记为 prerelease 的 GitHub 候选；它不能是现有线上 stable，也不能改 `latest`。
- 将本分支的受保护管理工作流落到 GitHub 远端后，用只读 `release status` 验证 staging Cloudflare token 的真实权限。
- 一个比基线高的测试版本，例如 `.2 → .3`，以及对应的 Core/Runtime 固定 tag/SHA。

匹配仓库公钥的 staging Tauri 私钥、自签名 staging Authenticode 身份、其余 Environment 配置，以及 `primelab-win` outbound-only runner 已准备好。自签名身份只用于该专机的 prototype Nightly；它不是 canary/beta/stable 的可信发布证书。

### 进入 beta/stable 前

- production 签名身份和 D1/Worker，与 staging 完全分离。
- macOS arm64/x64 的 Developer ID、notarization 和 staple 证据。
- 电信、联通、移动、企业/校园网络抽样结果。
- 告警阈值、值班人、暂停权限和人工恢复包。
- 首个带 updater 的正式“承重版本”手工覆盖安装计划。

## 3. 当前卡点

| 卡点 | 为什么是卡点 | 处理方式 |
|---|---|---|
| 没有获准创建新的公开 prerelease | GitHub 直连回退要求资产无需客户端 GitHub 凭据；真实 E2E 必须有公开候选 | 本轮只实现和本地/staging 校验；获得单独发布授权后再建候选 |
| Cloudflare CI token 尚未通过 Actions 验证 | Secret 已写入 `hot-update-staging`，但管理工作流仍只在本地分支，远端无法 dispatch | 工作流经正常 push/PR 落地后，先跑只读 `release status`，再允许任何写操作 |
| Windows 正式 Authenticode 尚未采购 | staging 自签名身份只对专机显式信任；Tauri 签名也不能替代 Windows 对 EXE 发布者的信任 | 采购/配置证书和 RFC 3161 时间戳，canary/beta/stable 强制验证 |
| Cloudflare 免费网络无大陆 SLA | 自定义域名在一台机器可达不代表全国可达 | 多运营商采样；控制面失败保持当前版，下载失败允许 GitHub 回退 |
| 新链路未做真实安装 | 单测只能证明分类和契约，不能证明安装器退出/重启/9120/注册表 | 用新候选按 09 的顺序验收 |

## 4. 什么已经解决

- Desktop `0.8.x ↔ Core 0.20.x` 已进入机器可读兼容矩阵。
- 客户端不会把 Bearer token 发送给下载 Worker 或 GitHub。
- Cloudflare 失败只对可恢复的网络/429/5xx做一次完整包重下；签名、格式、401/403、404不回退。
- 控制面不可达不会去 GitHub发现新版本。
- token 可从一次性邀请导入系统凭据库，配置文件只保存 endpoint/channel/device ID。
- 下载完成可“立即重启/稍后”，Windows pending 包可在下次启动恢复。
- 发布注册只能从真实 GitHub资产和 `release-record.json` 反推 SHA、大小、签名和 Core 元数据。
- promotion、调比例、暂停、撤销都有 D1 审计事件。
- 两个 staging Worker 和 D1 追加迁移已经部署；production 未部署。
- `primelab-win` runner 已使用专用标签在线，运行于交互式 Windows 会话，能承载 WebView2/CDP 冒烟。
- staging Cloudflare token、Tauri 私钥、专机 token、Runtime tag、baseline 路径和 staging Authenticode 身份已进入受保护 Environment；没有触发 Nightly 或发布工作流。

## 5. 不应误解的边界

- “指定用户可更新”不等于“安装包保密”。公开 prerelease 的 URL 可能被任何人获得，但应用只向被授权设备自动下发。
- GitHub 是下载备用源，不是发现备用源。
- 暂停只能阻止新安装；已经升级的机器不会自动降级。
- `stable` 不由 beta 记录改名，而是重新用正式版本号和 production 身份构建。
- 第一版不做差分或真正断点续传；回退会重新下载约 185 MB 的完整包。
