# O-04：研究—事实核查—编辑

## 1. 适用目标

把“收集资料”“判断资料是否可信”和“形成可发布文本”拆给不同角色，避免同一个 Agent 在写作时顺手把未经证实的内容润色成事实。

适合：

- 竞品、行业或政策资料整理；
- 带来源的技术调研；
- 需要保留不确定性和反方证据的文章；
- 对时间敏感、可能发生变化的信息进行交叉验证。

## 2. 房间配置

**建议房间顺序：**

```text
researcher
fact-checker
editor
```

不要使用普通消息一次触发三人。编辑必须等事实核查结束后再工作。

## 3. 角色卡

### `researcher`

**Profile 描述：**

```text
收集事实、来源、时间和置信度，不负责把资料直接写成最终稿
```

**核心指令：**

```text
你是研究员。把用户问题拆成可核验事实，并为每条事实保存来源、发布时间、访问时间和原始上下文。
优先使用一手、官方或原始资料；二手资料必须标记。
无法访问或无法核验的内容写为“待核验”，不得补写不存在的来源。
输出事实表，不写最终文章。
```

### `fact-checker`

**Profile 描述：**

```text
逐条验证研究员事实，查找来源冲突、时间失效和证据缺口，不负责润色
```

**核心指令：**

```text
你是事实核查员。逐条检查 researcher 的事实表。
每条只能标记：已证实、部分证实、存疑、错误、已过时。
说明判定依据、冲突来源和仍需补充的证据。
不因为多个网页重复同一说法就视为独立证据，不把搜索摘要当作原始来源。
```

### `editor`

**Profile 描述：**

```text
只使用核查通过的材料形成成稿，并保留来源、不确定性和时间边界
```

**核心指令：**

```text
你是编辑。只在事实核查完成后写作。
“已证实”内容可作为事实；“部分证实”必须保留限定语；“存疑、错误、已过时”不得写成确定结论。
重要结论必须保留来源标记。不要为了文风连贯删除不确定性或反方证据。
```

## 4. 统一事实记录

研究员使用以下结构，后续角色不得丢失 `fact_id`：

| 字段 | 含义 |
|---|---|
| `fact_id` | 稳定编号，例如 `F-001` |
| 事实陈述 | 一句话、可判断真伪 |
| 来源标题 | 来源可读名称 |
| URL / 文件 | 可回到原始材料的位置 |
| 发布时间 | 来源自身时间 |
| 访问时间 | 实际获取时间和时区 |
| 来源层级 | 一手 / 官方 / 二手 / 未知 |
| 直接证据 | 支持该事实的摘要或短摘录 |
| 置信度 | 高 / 中 / 低 |
| 限制 | 样本、地域、版本或时间边界 |

不要把一个包含多个主张的长句放在同一个 `fact_id` 中。

## 5. 编排步骤

### 第 1 轮：研究

```text
@researcher

研究问题：[填写]
时间边界：[填写]
地域或版本边界：[填写]
允许使用的来源：[填写]

请输出事实表。每条事实分配 fact_id，并记录来源、发布时间、访问时间、
来源层级、证据、置信度和限制。没有来源的内容标记“待核验”。
```

### 第 2 轮：事实核查

```text
@fact-checker

逐条核查上一轮 researcher 的事实表。
保持原 fact_id，并输出：
- 状态：已证实 / 部分证实 / 存疑 / 错误 / 已过时；
- 判定依据；
- 来源冲突；
- 时间或版本问题；
- 补证建议。

优先指出会改变最终结论的问题。
```

### 可选第 3 轮：补证

只有核查员给出明确缺口时才执行：

```text
@researcher

请只补充上一轮标记为“部分证实”或“存疑”的以下 fact_id：[填写]。
保留原记录，新增来源时说明它解决了哪个证据缺口。
```

补证后再次定向 `@fact-checker`，不能由研究员自行把状态改成“已证实”。

### 最终轮：编辑

```text
@editor

请根据最近一次事实核查结果形成成稿。
规则：
1. 只把“已证实”写成确定事实；
2. “部分证实”保留限定语；
3. 不使用“存疑、错误、已过时”的陈述；
4. 重要结论保留 fact_id 和来源；
5. 文末单列未知项、适用时间和版本边界。

成稿结构：[填写]
目标读者：[填写]
长度：[填写]
```

## 6. 最终产物

应同时保留三层材料：

1. 原始事实表；
2. 事实核查表；
3. 最终成稿。

只保存成稿会丢失证据链，无法复核编辑是否越过核查结果。

## 7. 验收与失败判据

### 通过

- fact-checker 能引用 researcher 的具体 `fact_id`；
- 每条重要结论都有可访问来源和时间；
- editor 没有把“存疑”写成确定事实；
- 成稿保留版本、地域和时间边界；
- 来源冲突没有被静默删除。

### 失败

- researcher 伪造 URL、标题或访问时间；
- fact-checker 只重复事实，没有给状态和依据；
- 多个转载页面被当成多个独立来源；
- editor 添加核查表中不存在的新事实；
- 为追求简洁删除所有限定语；
- 输出或日志包含凭证、付费内容全文或个人敏感信息。

## 8. 工具与安全

- 涉及时效性事实时必须实际检索，不依赖模型记忆；
- 优先官方文档、原始数据和论文；
- 引用遵守版权限制，不复制大段受保护内容；
- 保存 URL 和访问时间，不只保存搜索结果摘要；
- 需要登录的来源不得把 Cookie、Token 或账号信息交给群聊；
- 发布仍是独立外部动作，本编排只生成待审稿件。
