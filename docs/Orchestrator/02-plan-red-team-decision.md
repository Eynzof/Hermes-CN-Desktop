# O-02：方案—红队—决策

## 1. 适用目标

用四个明确回合形成“提出方案 → 找出反例 → 针对性修订 → 独立决策”的闭环。

适合：

- 发布、迁移、上线和回滚方案；
- 权限、安全或数据处理流程变更；
- 需要证明方案经受过反对意见，而不是只生成一份看似完整的计划。

## 2. 房间配置

**建议房间顺序：**

```text
planner
critic
decision-maker
```

本模式的关键不是三个角色同时回答，而是每一轮只触发一个角色。把 `@planner @critic` 放在同一轮不会形成辩论。

## 3. 角色卡

### `planner`

**Profile 描述：**

```text
提出可执行方案并根据红队意见修订，必须公开假设、依赖和退出条件
```

**核心指令：**

```text
你是方案提出者。先把目标转成步骤、依赖、负责人、验证点和退出条件。
初版必须标记 PLAN-V1；修订版必须标记 REVISION-V2，并逐条回应 critic。
只修改经证据支持或能降低关键风险的部分，不为迎合批评而重写全部方案。
```

### `critic`

**Profile 描述：**

```text
以红队视角寻找可证伪反例、遗漏和不可逆风险，不直接重写方案
```

**核心指令：**

```text
你是红队审查者。只审查上一轮 planner 的方案。
每项问题必须包含：被质疑的假设、反例或失败路径、影响、可验证方法、严重度。
至少给出一个会阻止执行的条件。不要替 planner 写完整替代方案。
```

### `decision-maker`

**Profile 描述：**

```text
比较初版、红队意见和修订版，按统一量表作出可追溯决策
```

**核心指令：**

```text
你是独立决策者。必须区分 PLAN-V1、critic 的审查和 REVISION-V2。
按成本、风险、可逆性、验证难度各自评分，并检查关键反对意见是否被解决。
最终只能选择：批准、附条件批准、退回修订、拒绝。
```

## 4. 编排步骤（四轮）

### 第 1 轮：初版

```text
@planner

目标：[填写]
硬约束：[填写]
已知事实：[填写]

请输出标记为 PLAN-V1 的初版方案，必须包含：
- 明确假设；
- 分阶段步骤；
- 依赖和负责人；
- 每阶段验证点；
- 退出与回滚条件；
- 当前未知项。
```

### 第 2 轮：红队

```text
@critic

审查上一轮 PLAN-V1。
至少给出三个可证伪风险，并逐项写明：
1. 对应的方案步骤或假设；
2. 失败路径；
3. 影响和严重度；
4. 最小验证实验；
5. 是否构成阻断条件。

不要重写整份方案。
```

### 第 3 轮：修订

```text
@planner

结合上一轮 critic 的审查，输出 REVISION-V2。
先逐条标记“接受 / 部分接受 / 拒绝”，并给出理由和证据；
再列出相对 PLAN-V1 的变更；
最后给出更新后的执行步骤和退出条件。
不要删除仍未解决的风险。
```

### 第 4 轮：决策

```text
@decision-maker

比较 PLAN-V1、critic 的审查和 REVISION-V2。
按成本、风险、可逆性、验证难度分别给 1～5 分并解释。
列出：已解决风险、剩余风险、必须先满足的条件。
最终选择“批准 / 附条件批准 / 退回修订 / 拒绝”，并说明改变结论的条件。
```

## 5. 输出契约

最终决策至少包含：

```text
决策：
评分：
已解决风险：
剩余风险：
前置条件：
验证计划：
退出条件：
复核点：
```

评分只是帮助比较，不能替代对阻断条件的判断。即使总分较高，只要存在未解决的不可逆高风险，也可以拒绝。

## 6. 验收与失败判据

### 通过

- sender 顺序为 planner → critic → planner → decision-maker；
- critic 明确引用 PLAN-V1 的具体假设或步骤；
- REVISION-V2 对每条红队意见作出可追溯处理；
- 决策者能区分初版和修订版；
- 最终结论包含剩余风险和改变结论的条件。

### 失败

- planner 和 critic 同轮回答，却声称形成了辩论；
- critic 只表达偏好，没有可验证反例；
- planner 删除反对意见但没有解释；
- decision-maker 只总结，没有作出明确选择；
- 角色执行了未经授权的部署、提交、发布或外部消息动作。

## 7. 变体

### 双红队

可增加 `security-critic` 和 `delivery-critic`。两名 critic 可以在同一轮独立审查，因为它们读取相同 PLAN-V1，不需要互相回应。

### 多次修订

若 REVISION-V2 仍有阻断问题，可以重复 critic → planner，但每版必须使用新标记，例如 `REVISION-V3`，避免历史中版本混淆。

### 快速决策

低风险、可逆任务可以省略第二次红队，但不能省略退出条件和验证点。
